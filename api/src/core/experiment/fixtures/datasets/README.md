# Vendored public benchmark datasets

These JSONL files are verbatim copies of public benchmark datasets, vendored so
experiment runs are hermetic (no network fetch, no non-determinism). They are
consumed by `../../experiment-dataset-loader.ts`, which maps each record onto an
`ExperimentTask` graded by the existing objective pipeline (sandbox execution
for HumanEval / HumanEval+, `numeric_equals` answer-check for GSM8K). No LLM
judge is involved.

## `humaneval.jsonl` — HumanEval (164 problems, complete)
- Source: https://github.com/openai/human-eval (`data/HumanEval.jsonl.gz`)
- License: MIT © OpenAI
- Fields per line: `task_id`, `prompt` (function stub + docstring),
  `entry_point` (function name), `canonical_solution` (reference; not sent to
  the model), `test` (a native `check(candidate)` harness).
- Grading: the model completes the function; the loader carries the native
  `test` harness as `codeTest.checkSource` and the runner runs it unmodified
  in the sandbox — binary pass@1 (all asserts pass → 1.0, else 0.0).

## `humaneval_plus.jsonl` — HumanEval+ / EvalPlus (164 problems, complete)
- Source: EvalPlus `HumanEvalPlus` (v0.1.10) —
  https://github.com/evalplus/evalplus (dataset release `HumanEvalPlus.jsonl`).
  Cite: Liu, Xia, Wang, Zhang, "Is Your Code Generated by ChatGPT Really
  Correct? Rigorous Evaluation of Large Language Models for Code Generation",
  NeurIPS 2023.
- License: Apache-2.0 © the EvalPlus authors.
- What it is: the SAME 164 HumanEval problems, but each carries ~999 extra
  augmented test inputs (`plus_input`) generated by type-aware mutation and
  differential-tested against the reference solution. This un-saturates the
  ceiling plain HumanEval cannot express (frontier best-of-10 solves 98.1% of
  HumanEval; the augmented tests drop frontier pass@1 ~10-20pts by catching
  edge-case bugs the 7 base asserts miss).
- Fields per line: `task_id`, `prompt`, `entry_point`, `canonical_solution`
  (the reference body that completes `prompt` to define `entry_point`), `test`
  (the original 7-assert harness — NOT used), `base_input` (~7 original
  arg-lists), `plus_input` (~999 augmented arg-lists), `atol` (float tolerance,
  usually 0), `contract` (EvalPlus input-validation contract — ignored).
- Grading: the loader reconstructs the reference from
  `prompt + canonical_solution` and generates a DIFFERENTIAL-TEST
  `check(candidate)` harness (carried as `codeTest.checkSource`) that asserts
  the candidate agrees with the reference — same value, or same raised
  exception type — on every capped input. Inputs are capped deterministically
  at `HUMANEVAL_PLUS_MAX_TESTS = 200` (all `base_input`, then a prefix of
  `plus_input`; no RNG). Binary pass@1 via the same sandbox path as HumanEval;
  no judge.

## `livebench_reasoning.jsonl` — LiveBench reasoning (200 rows, complete snapshot)
- Source: https://huggingface.co/datasets/livebench/reasoning (config `default`,
  split `test`), fetched via the HF datasets-server. Scorers vendored separately
  under `../livebench_scorers/reasoning/` (see that dir's README).
  Cite: White et al., "LiveBench: A Challenging, Contamination-Free LLM
  Benchmark" (2024), https://livebench.ai — Apache-2.0.
- License: Apache-2.0 © the LiveBench authors.
- Why this axis: LiveBench is **monthly-refreshed against contamination**, and
  reasoning is scored against a held-out ground truth with **no LLM oracle**.
  This is the contamination-free, oracle-free axis for the Ailin¹ Collective
  Intelligence thesis. Critically, the ground truth is used for **SCORING ONLY**
  and is **NEVER forwarded to the collective** — it rides `groundTruthScorer`
  (a NON-forwarded field, like `codeTest`), not `answerCheck` (which IS forwarded
  as `ailin_constraints.answer_check`). Forwarding it would re-introduce the
  "oracle" contamination that invalidated the old objective axis.
- Fields per line: `question_id`, `category` (`reasoning`), `ground_truth`
  (held-out gold — scoring only), `turns` (array; `turns[0]` is the full prompt
  incl. LiveBench's own answer-format instruction), `task` (subtask name),
  `livebench_release_date`, `livebench_removal_date` (`""` = still active in the
  live set), `level`.
- Subtasks present: `zebra_puzzle` (100), `spatial` (50), `web_of_lies_v2` (50).
- Grading & loader coverage (`loadLiveBenchReasoningTasks`): the loader carries
  LiveBench's own vendored scorer for the row's subtask as
  `groundTruthScorer.scorerSource` and the runner executes it in the SAME sandbox
  path as `codeTest`, scoring a continuous 0..1 (partial credit where the scorer
  defines it — e.g. current zebra) against `ground_truth`. **Covered subtasks:**
  `zebra_puzzle` (current `<solution>` format, active), `spatial`,
  `web_of_lies_v2` (validated perfect-answer→1.0 / wrong→0.0). **Excluded:** the
  pre-2024-11-25 `zebra_puzzle` block (50 rows, retired old `***X***` format) —
  its `zebra_puzzle_process_results_old` scorer mis-scores hyphenated /
  special-char ground truths (`police-officer`, `d&b`) and cannot be made
  faithful, so the loader drops it (net **150** graded rows). The full 200-row
  snapshot is retained here so operators can re-derive or filter differently.

## `gsm8k.jsonl` — GSM8K (first 200 test problems)
- Source: https://github.com/openai/grade-school-math
  (`grade_school_math/data/test.jsonl`, full test split is 1319 problems)
- License: MIT © OpenAI
- Subset: the first 200 lines of the test split, taken deterministically to
  keep the fixture and any run bounded (the full 1319 × arms × repetitions
  would blow past the per-config budget cap). To use the full set, replace
  this file with the complete `test.jsonl`.
- Fields per line: `question`, `answer` (chain-of-thought ending with
  `#### <integer>`).
- Grading: the loader extracts the integer after `####` into a
  `numeric_equals` answer-check; the model is asked to end with `FINAL: <n>`,
  which the objective grader isolates. No sandbox, no judge.
